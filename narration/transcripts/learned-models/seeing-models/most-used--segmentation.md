This page explains segmentation, which means models that mark the exact pixels of each object in a picture instead of drawing a box around it. It answers five questions: what a segmentation model does, what the difference is between its two main kinds, how it works inside, how it is trained, and why a robot arm often needs an outline rather than a box. 

It is written for a reader who has already learned about image classification and object detection, because it uses words like pixels, scores, the backbone, fine-tuning, boxes, and confidence without explaining them again.

To begin with what it is, a segmentation model is a model that gives an answer for every single pixel of a picture, because for each pixel it says what that pixel belongs to. The answer for a whole picture is called a mask, and a mask is a second picture of the same size as the photo. In the mask, each pixel holds a class or an object number instead of a colour. You can think of it as the photo with every object painted in its own flat colour.

Here is an everyday example. Imagine a colouring book page, and a child who colours every mug blue, every bottle green, and the table brown, staying strictly inside the lines. Once they finish, every part of the page has one colour, and that colour says what the part is. A segmentation model produces the same kind of result from a photo.

The difference from a detector is the level of detail. A detector says there is a mug inside a certain rectangle, while a segmentation model says these exact pixels are the mug. So the pixels outside the mug's edge are not mug, even when they lie inside the rectangle.

The next part of the page explains what goes in and what comes out. The input is one camera picture, exactly as it is for a detector, but the output is one or more masks rather than boxes. There are two main kinds of segmentation, and they give different outputs.

The first is semantic segmentation. This gives every pixel a class, so it says "this pixel is mug", "this pixel is table", and "this pixel is wall". However, it does not tell one mug from another, which means two mugs standing side by side become a single "mug" area.

The second is instance segmentation. This gives each separate object its own mask, so it says "these pixels are mug 1" and "these pixels are mug 2". Each object is called an instance, and the background, such as the wall and the table, is usually left out.

The page shows a diagram of the same photo with both kinds of answer. In the semantic panel, two mugs share one colour, because they are the same class. In the instance panel, each mug has its own colour, because each of them is a separate object.

A third kind, called panoptic segmentation, does both at once. It gives every pixel a class and also separates the objects. The word "panoptic" itself means "seeing everything".

A robot arm that picks objects usually needs instance segmentation, because it has to pick one particular mug rather than "the mug area". Semantic segmentation is more useful for questions about places, such as which part of the picture is table, where the free space is, or which pixels belong to a person who has walked into the cell.

An instance segmentation model gives a list with one item per object. Each item has the object's class, a confidence score, and a mask. Most models also give the object's box, since the box is easy to work out from the mask.

The page then explains why an outline is better than a box. A box holds the object, but it also holds whatever happens to be around the object. A diagram compares a box and a mask for a single mug. Inside the box, many pixels are just the wall, the table, or the empty gap inside the mug's handle. The mask, however, covers only the mug itself, and it clearly shows the gap inside the handle, which a box cannot show at all.

For a robot arm, this matters in three ways. First, the middle of the mask is the true middle of the mug, while the middle of the box is pulled off-centre towards the handle. Second, the depth pixels inside the mask all belong to the mug, whereas the depth pixels inside a box include the table behind it. So a mask gives much cleaner 3D points for the object. Finally, the mask shows the shape, so the program can find the handle, the rim, or the narrowest part, and then choose exactly where the fingers should go.

Moving on to how it works inside, these two kinds of output are produced in two different ways. 

The first way is usual for semantic segmentation, and it involves shrinking the picture and then growing it back. A classifier's backbone makes the grid of numbers smaller and smaller, because that is how it learns what is in the picture. But a mask must be as big as the photo, with one answer per pixel. So a semantic segmentation model adds a second half that makes the grid big again. 

The first half is a normal backbone, which shrinks the picture step by step. At each step the grid gets smaller, and each number carries more meaning. This half is called the encoder. The second half grows the grid back, step by step, until it is the size of the photo again. This half is called the decoder. At each step of the decoder, the model copies in the grid of the same size from the encoder. The small grids know what is in the picture, while the large grids from the encoder still know exactly where the edges are. Joining them gives an answer that is both right about the class and sharp at the edges. These copies are called skip connections. At the end, each pixel gets one score per class, and the pixel takes the class with the highest score.

A diagram shows this idea on a tiny eight by eight picture. The picture shrinks to find what is there, then grows back to say which pixel is which, with arrows showing the skip connections. Once the model is drawn this way, it looks like a letter U, which is where the famous U-Net model got its name.

The second way is usual for instance segmentation, and it works by taking a detector and adding a mask to it. First, a detector finds the boxes. Second, for each box, the model cuts out the matching part of the backbone's grids. Third, a small extra network, called the mask head, looks at that cut-out part, and gives a small mask, often 28 by 28 pixels, that says which pixels inside the box are the object. Finally, the small mask is stretched to the size of the box in the photo. Because each box gets its own mask, two mugs that touch still get two separate masks. This is exactly how Mask R-CNN works. Newer models use a transformer instead, where each query gives one object, and each object comes with a mask rather than only a box. This is how Mask2Former works, meaning one such model can do semantic, instance, and panoptic segmentation all at once.

The next section covers how segmentation models are trained. Whichever way a model is built, it learns from pictures where a person has marked the exact outline of every object. This is much slower than drawing boxes. For each object, the person clicks many points around its edge to trace a shape, called a polygon. A picture with ten objects can take several minutes to label, where boxes would take less than one.

Two public collections of labelled pictures are used most often. COCO, the same collection used for detectors, has an outline for every labelled object. Most instance segmentation models you can download were trained on its 80 classes. ADE20K is used for semantic segmentation instead, because it labels whole scenes with 150 classes of things and places, including walls, floors, and tables.

Training works in the same way as it does for a detector. The model gives its masks for a batch of pictures, and a program compares every pixel of each mask with the traced outline. It counts how many pixels are wrong, and nudges the network's numbers to reduce that count. 

A robot project usually fine-tunes, starting from a model trained on COCO and training it on a few hundred of its own pictures. To save labelling time, most tools now use a promptable model to trace the outline. The person clicks once on the object, the model draws the outline, and the person only fixes its mistakes. Pictures from a simulator help even more, because the simulator knows which object each pixel belongs to, producing perfect masks for free.

The page then lists several well-known models. U-Net came out in 2015 for pictures of cells under a microscope, and its shrink-then-grow shape is now used in many other models. Mask R-CNN is an instance segmentation model from 2017 that adds a mask head to a detector. DeepLab is a family of semantic segmentation models from Google that looks at the picture at several scales at once. Mask2Former is a transformer model from Meta. YOLO segmentation models are fast versions of YOLO detectors that also give a mask for each box, making them the easiest way to get masks from a live camera. Finally, SAM, the Segment Anything Model from Meta, does not have a list of classes at all. You click on an object, and it gives the exact outline.

To show where this is used on a robot arm, the page gives a worked example of picking up a mug by its body rather than its handle. First, a depth camera above the table takes a colour picture and a depth picture. Second, an instance segmentation model gives a mask for each mug. Third, the program chooses one mug. Fourth, it takes every depth pixel inside that mug's mask, and turns each one into a 3D point in metres. The result is a small cloud of points that belong only to the mug, with no table points mixed in. Fifth, it finds the handle, which is the thin part of the mask sticking out, and the main body, which is the wide round part. Sixth, it places the gripper on the side of the body away from the handle. Finally, the arm moves to that pose, closes the gripper, and lifts. A box alone could not do this, because the box's depth pixels would include the table, and the box does not show where the handle is.

Other common uses include picking overlapping parts from a bin, finding free space on a table to put an object down, keeping people safe by slowing the arm when a person's pixels appear near it, and giving a clean, isolated object to a grasp model or a 3D model.

However, things do go wrong. Segmentation models fail in some of the same ways as detectors, and in a few ways of their own. First, the edges are rough. Masks are often a few pixels off, which can cut off thin parts like a handle or a cable. The fix is a higher resolution picture or running a model like SAM on the detector's box. Second, touching objects of the same kind can merge into one mask, or one part may be split into two. The fix is to include crowded scenes in training. Third, see-through and shiny objects are hard to see, so their masks are often wrong. Fourth, a mask says nothing about depth or turn; it only gives flat pixels. The fix is to combine it with a depth camera or a pose model. Fifth, unknown objects are missed entirely, just as they are with a detector. Finally, segmentation is slower than detection, because giving an answer for every pixel costs more work.

Summarising why to use segmentation and what it costs, the page notes that it gives the robot the exact shape of each object, and clean 3D points when combined with depth. The obvious alternative is an object detector, which is faster and easier to label. You should choose segmentation when the shape decides the grasp, like a mug with a handle, or when parts touch in a bin. The costs are that labelling outlines takes much longer, the models are larger and slower, and a mask is still only a flat shape, meaning the robot still needs depth before it can reach for the object.

There is also a written alternative to using a trained network. You can make masks with written rules, using thresholding to isolate a colour or a height above the table, and then using morphology to remove specks and fill holes. Clustering then turns the mask into one piece per object. This written way wins when each object has a unique colour or height, because it runs in milliseconds and needs no training. The segmentation model wins when objects touch, when they share colours with the background, or when they vary too much for any one rule to cover.

The quickest way is to use a YOLO segmentation model from the Ultralytics library, because it gives a box and an outline together in a single pass. For each object, it takes the box and the outline, looks up the object's name, calculates the centre of the outline, and prints this information out. 

The results also hold the mask as a grid of true and false values. That form is exactly what you want when you need to pick out the depth pixels that belong to a single object, because you can use it directly to select from the depth image. 

Because the pretrained model already knows the 80 COCO classes, a mug on a table is outlined without any training from you, saving you the massive effort of tracing outlines by hand. What you still have to write yourself is the step from a mask to a place in the room. You have to select the depth pixels inside the mask, average them into a point in metres, and work out a direction for the gripper. The library gives you the shape in the picture, never the pose on the table. 

Ultimately, you have to decide if you need an outline at all, because a detector is faster when a box is enough. Then you decide your confidence threshold, and finally, whether to fine-tune. If your parts are not among the standard classes, you have to fine-tune, and the cost is real, because every training picture will need an outline traced around every object.
