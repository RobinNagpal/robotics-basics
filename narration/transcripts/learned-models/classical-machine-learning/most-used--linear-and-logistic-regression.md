Linear and logistic regression. This page explains the two simplest learning methods there are. Linear regression learns to predict a number, such as how many newtons a sensor reading means. Logistic regression instead learns to predict the chance of a yes, such as the chance that a grasp will hold. The page also covers two small changes that make linear regression work much better in practice. These are ridge regression, which stops a fit from going wild, and weighted least squares, which lets you trust some readings more than others.

It answers five questions, taking them in turn. What do these methods do? How do they work, step by step? What data do they need? Where does a robot arm use them? And what goes wrong?

It is for a reader who has read the first chapter of this book, especially the page on how a model learns. So you need to know what an example, a label, a weight and overfitting are before you start.

Every number on this page comes from a real run of a script where the data is simulated so that the true answer is known exactly. But the methods themselves are real, and they are written in NumPy. Before this page, it helps to have read the page on least-squares fitting in Book 5, because linear regression is least-squares fitting used to learn from examples.

The first section gives the idea in one sentence. Linear regression multiplies each input number by a weight, adds the results, and picks the weights that make the squared mistakes on the examples as small as possible. Logistic regression does the same sum and then squeezes it into a chance between zero and one.

For example, a taxi fare is a fixed starting charge plus a price per kilometre. So if you did not know those two prices, you could look at ten old receipts, each with a distance and a fare, and work the prices out from them. The starting charge and the price per kilometre are the two weights, so finding them from the receipts is linear regression.

Now say you want to know whether the taxi will arrive within ten minutes, where the answer is yes or no rather than a number. You could still add up the same kind of weighted sum, from the distance and the time of day, and then turn that sum into a chance such as zero point eight, and that is logistic regression.

The next part of the page explains linear regression, step by step. The one-sentence idea just given does not say how the weights are chosen, so this section takes the method apart. Linear regression takes a list of input numbers for each example, and these input numbers are called features. From them it produces one output number. This output equals a constant, plus the first weight times the first feature, plus the second weight times the second feature, and so on.

The constant and the weights are what needs to be chosen, so training means choosing them. For every example, the residual is the label minus the output, which says how far off the prediction is. Linear regression then chooses the weights that make the sum of the squared residuals as small as possible. This is exactly least-squares fitting from Book 5, and the only difference is the purpose, because here the fitted line is used to predict new cases.

To show a worked example, imagine calibrating a force sensor. A gripper has a force sensor that reports a raw number, called counts. To turn counts into newtons, the robot hangs five known loads on it and writes down what the sensor reports for each one. So each pair is one example, where the input is the counts and the label is the known load.

The page shows a table of these five examples. The known loads rise from zero to twenty newtons in steps of five, and the reported counts rise from one hundred and two up to one thousand one hundred and three. Because there is only one feature, the best line has a short formula with five steps. 

First, find the average input and the average label, which here are six hundred and two point six counts and ten point zero newtons. Second, for every example, take its input minus the average input and its label minus the average label. Then multiply the two and add up the five results, which gives twelve thousand five hundred and fifteen point zero. Third, for every example, square its input minus the average input, and add up the five results, which gives six hundred and twenty-six thousand, six hundred and five point two. Fourth, the slope is step two divided by step three, which is zero point zero one nine nine seven newtons per count. Finally, the constant is the average label minus the slope times the average input, which works out to minus two point zero three six newtons.

So the learned rule is that the load equals minus two point zero three six, plus zero point zero one nine nine seven times the counts. This means a new reading of seven hundred counts becomes eleven point nine five newtons. The residuals on the five examples are all under zero point two newtons, so the line fits the readings well. With more than one feature the same idea is solved as a small set of equations, and every library does that for you in one call.

The next section is about making features by hand, which lets a line bend. The previous example fitted a straight line, but a straight line cannot follow a curve. However, the word "linear" in linear regression only means that the output is a weighted sum of the features, and it says nothing about what those features are. So you can make extra features by hand from the input you already have, such as the input squared and the input cubed. The fit then stays a weighted sum, but the shape it draws can bend.

The example here is a depth camera whose readings are a little wrong, by an amount that changes with distance. The robot measures a flat board at thirty known distances between zero point three and one point five metres, and records the error of each reading in millimetres. To score a fit, the script compares it with the true error curve at four hundred distances and reports the typical difference, which is the root mean square error. That means squaring each difference, taking the average and then taking the square root.

A diagram shows the thirty examples fitted with a straight line, and then with a curve made from distance, distance squared and distance cubed. With the features of one and distance, the fit is a straight line, and it is off by two point five six millimetres. Adding distance squared brings this down to zero point six five millimetres, and adding distance cubed as well brings it to zero point five nine millimetres. Nothing about the method changed in any of this, because only the columns of the table changed.

Choosing features by hand is where most of the skill in linear regression lies, because good features come from knowing the physics. For example, for a joint's friction a person might add the sign of the speed as a feature, because friction pushes against the motion. For a camera lens, the distance from the picture's centre squared is a common feature, because lens bending grows that way.

The page then moves to ridge regression, which puts a penalty on big weights. More features let the curve bend more, but with too many features for the number of examples it bends wildly to pass through every noisy point. That is overfitting, and the sign of it here is that the weights become huge and cancel each other out.

Ridge regression fixes this with one change, because it adds a penalty to the thing being made small. This penalty is the sum of the squared weights, times a number called lambda. The fit must now balance two wishes, which are to stay close to the examples and to keep the weights small. The constant is not penalised, because shrinking it would only move the whole curve up or down.

For example, the script gave twelve examples to a curve with ten weights, which are powers of the distance up to the ninth. With no penalty, the largest weight is one thousand two hundred and eighty-eight, and the curve is off by sixteen point six millimetres. With a very small penalty, where lambda is zero point zero zero zero zero zero one, the largest weight is four hundred and twenty-two and the curve is off by four point two millimetres, which is still wild between the examples.

How big should lambda be? You cannot use the true curve here, because in real life you do not have it. Instead you use leave-one-out checking, which means leaving out one example, fitting on the other eleven, and seeing how far off the prediction for the left-out one is. Then do this for each of the twelve examples in turn and average the results, and keep the lambda with the lowest average.

A diagram shows fits with almost no penalty, the chosen penalty, and too much penalty, alongside a graph of the leave-one-out error for each penalty size. Leave-one-out checking picked a lambda of zero point zero five six, whose fit is off by one point three nine millimetres against the true curve and whose largest weight is six point one. But with a lambda of one hundred the penalty is too strong, so the curve is almost flat and it is off by three point two millimetres. The graph shows that the check picked a good value. Notice the left end of the chosen curve, where there are no examples below zero point four metres, so the curve rises where it has no data. This means ridge regression only keeps a curve calm between the examples, and not beyond them.

The next part covers weighted least squares, which means trusting some readings more. Plain least squares treats every example as equally reliable, but often the examples are not equally reliable. For example, a depth camera is less accurate far away than close up, and a force reading taken while the arm is moving has more noise than one taken with the arm still.

Weighted least squares gives each example a weight of its own, and it makes the sum of the weight times the squared residual as small as possible. A reading with a big weight pulls the line hard, while a reading with a small weight pulls it only gently. The usual choice is for the weight to equal one divided by the reading's noise squared, so a reading that is five times less noisy gets twenty-five times the say. If you do not know the noise you can measure it, by repeating a few readings at the same load and seeing how much they vary.

So the example calibrates the force sensor again, this time with thirty readings. Twenty were taken with the arm still, which gives a noise of about zero point two newtons, but only with light loads, below about six hundred counts. Ten were taken while the arm moved, which gives a noise of about one newton, but they cover the whole range of loads.

A diagram shows these thirty calibration readings of two kinds, and how far the plain and weighted fits are from the true line. The still readings get weight twenty-five and the moving ones weight one. In this run, the plain fit's line is off by zero point two six newtons on average across the range, and the weighted fit's line by zero point zero four newtons. The picture shows why, because the plain line is tilted by the noisy readings, and it is worst at high loads, where it matters most.

One run can be lucky, so the script repeated the whole test two thousand times with fresh noise. On average the plain fit was off by zero point two four six newtons and the weighted fit by zero point one one seven newtons. Using only the twenty still readings gave zero point one two three newtons, so weighting did better than both of the alternatives. That is because weighting trusts the still readings most, but it still uses the moving ones to learn about high loads.

Weighting is not special to this page, because the same idea comes back on the page about decision trees and forests, where some examples count more when a tree is built, and on the page about nearest neighbours and locally weighted regression, where closer examples count more.

The next section explains logistic regression, which predicts the chance of a yes. Everything so far predicted a number, but many questions on a robot have a yes-or-no answer instead. Will this grasp hold? Is this part faulty? Did the peg go into the hole? These are called classification questions, and the answer to one of them is a class. Linear regression is a poor fit for them, because the script fitted a straight line to two hundred grasps labelled one for held and zero for dropped, and its outputs ran from minus zero point zero three to one point four zero. Neither of those two numbers is a sensible chance, because a chance has to lie between zero and one.

Logistic regression keeps the weighted sum, which it now calls the score, and passes it through an S-shaped curve called the logistic function, or sigmoid. The chance equals one divided by the result of one plus e to the power of minus the score. A score of zero gives a chance of zero point five zero, while a large positive score gives a chance close to one and a large negative score gives a chance close to zero. So the output is always a chance between zero and one.

For example, a robot deciding how hard to squeeze has logged two hundred past grasps. Each one has two features, which are the grip force in newtons and the width of the object in millimetres. The label is whether the object stayed in the gripper while the arm lifted it. In this simulation more force helps and a wider object is harder to hold, and one hundred and thirty-five of the two hundred grasps held.

Training uses gradient descent, which the page on how a model learns explained. The measure of how wrong the model is, called the loss, is the log loss. For a grasp that held, the loss is minus the log of the chance the model gave to "held". For a grasp that dropped, it is minus the log of the chance it gave to "dropped", so a confident wrong answer costs a lot. There is no one-step formula here as there is for linear regression, but the loss has a single lowest point, so gradient descent always finds the same answer. The features are first scaled to a similar size, so that one step size suits all the weights.

A diagram shows the S-curve that turns a score into a chance, alongside the two hundred logged grasps with the lines where the model gives a ten, fifty and ninety per cent chance of holding. The learned score is zero point six seven, plus zero point two six four times the force, minus zero point zero eight one times the width. On two thousand new simulated grasps it said the right answer, held or dropped, eighty-seven per cent of the time. The lines on the picture are where the chance is ten per cent, fifty per cent and ninety per cent. They are straight, because a fixed chance means a fixed score, and a fixed weighted sum is a straight line.

So the robot can now use the model before it acts. A table gives the chance of holding for three grasps. For a grip force of twenty newtons and an object width of forty millimetres, the score is two point seven two and the chance it holds is zero point ninety-four. If the width increases to seventy millimetres, the score drops to zero point three zero and the chance is zero point fifty-seven. But if the force is increased to thirty newtons for that seventy-millimetre object, the score goes up to two point ninety-four and the chance is zero point ninety-five.

For a seventy-millimetre object, the model says that twenty-seven point two newtons gives a ninety per cent chance of holding. The weights are also easy to read, because each extra newton adds zero point two six four to the score and each extra millimetre of width takes away zero point zero eight one. So about three millimetres of extra width needs about one newton of extra force to make up for it.

Features chosen by hand matter here too, because with grip force alone the model was right eighty point three per cent of the time on the new grasps, against eighty-seven point zero per cent with width added. This means the width column carried information that force alone could not give. When there are more than two classes, such as "held", "slipped" and "dropped", the same idea gives each class its own score. Then a function called softmax turns those scores into chances that add up to one.

The next section covers how they are trained, and how much data they need. Both methods have been shown on one worked example each, so this section says what they need in general. Both learn from a table, where each row is one example and each column is one feature, plus one more column for the label. You make the features yourself, from measurements that already mean something, such as a distance, a force or a temperature.

Linear and ridge regression are trained in one step, by solving a small set of equations, so training takes well under a second even for a million rows. Logistic regression instead takes a few hundred to a few thousand steps of gradient descent, which is still under a second for tables of this size.

So a rough rule for how much data you need is at least ten examples per weight. The force sensor had two weights and five examples, which worked because the readings were clean and the true shape really was a line. The ridge example had ten weights and only twelve examples, which is why it needed a penalty. For logistic regression you should count the rarer class rather than the rows, because if only twenty of your five hundred grasps dropped, the model has twenty examples of dropping to learn from and not five hundred.

Always keep some examples back for checking, as leave-one-out checking does, or split off a test set, because a fit that looks perfect on its own examples can still be wrong between them.

The next part explains where they are used on a robot arm. The previous section showed how little data these methods need, and because they are also small, fast and easy to check, they appear in many places on an arm. 

First, sensor calibration. Linear regression turns a force sensor's counts into newtons, a temperature reading into a correction, or a depth camera's reading into the true distance, and this page's two examples are both of this kind. Second, learning an arm's dynamics. The torque a joint needs is a weighted sum of known features built from the joint's angles, speeds and accelerations, where the weights are the links' masses and friction numbers. Finding the weights from logged motion is linear regression, often weighted, because some recorded motions are more reliable than others. Book 5's arm dynamics page describes the formula. Third, predicting grasp success from a few numbers. As in this page's example, logistic regression on force, width, mass or approach angle gives a quick chance that a grasp will hold. Fourth, a small head on a big network. A pretrained network turns each picture into a list of numbers, and a logistic regression then learns the robot's own classes on top of those numbers, from a few dozen labelled pictures. This is called a linear probe, and the fine-tuning page covers it. Fifth, correcting a physics formula. A formula predicts most of what happens, and a small linear regression learns what it gets wrong, as described on the page about learned dynamics models. Sixth, simple fault checks. A logistic regression on motor current, temperature and speed gives a chance that a joint is running abnormally. Finally, as a baseline. Before training anything bigger, people fit a ridge or logistic regression first, because if the big model cannot beat it, the big model is not worth its cost.

The next section is about what goes wrong. The previous section listed the jobs these methods do well, and this section lists the ways they fail instead. Each failure has a sign that you can look for, and the page provides a table collecting them. Here are the main things that go wrong and what people do about them. 

If the features cannot draw the true shape, the error stays high however much data you add, and the residuals show a pattern, such as all positive in the middle. To fix this, add features by hand, or move to decision trees and forests or Gaussian processes. If there are too many features for the examples, you will see tiny error on the examples but large error on new ones, along with very large weights. The fix is ridge regression, with lambda chosen by leave-one-out checking. If features are of very different sizes, the penalty shrinks some weights much more than others, and gradient descent is slow. You should scale every feature to a similar size first. If two features carry the same information, the weights jump around between fits and have opposite signs. You can drop one of them, or use ridge regression. If there are a few bad readings, the line tilts towards them. Use weighted least squares if you know which readings are poor, or RANSAC from Book 5 if you do not. If a new input is beyond the examples, the prediction runs off, as the ridge curve did below zero point four metres. You must collect examples there, or refuse to predict outside the known range. For logistic regression, if the two classes are perfectly separated, the weights keep growing as training goes on. Add a ridge penalty, which the scikit-learn library does by default. Finally, if there is a rare class in logistic regression, the model says "no" almost every time and still looks accurate. You should weight the rare class's examples more, and judge the model on the rare class.

The next part lists libraries. You would not write any of this from scratch in a real project, so the page lists real libraries for these methods. In Python, NumPy provides least-squares solvers that are enough for linear, ridge and weighted least squares in a few lines. The scikit-learn library in Python is the place to start. It provides linear regression, ridge regression, and logistic regression, along with tools for polynomial features and scaling. Its fit function takes a sample weight argument for weighting, and it has a tool that chooses lambda for you. Also in Python, statsmodels prints each weight with an error bar, which helps when you want to read the weights. For C++, Eigen provides least-squares solvers on matrices, which is used for fitting inside a robot's C++ control code. As a note, scikit-learn's logistic regression adds a ridge penalty by default, and its setting for it is called C, where a smaller C means a stronger penalty.

The next section explains why to use these methods, and what they cost. The libraries make these methods cheap to try, but the question is still when to choose them. These are the simplest learned models there are, and they turn a table of measured numbers into a number or a chance, using a weighted sum of features that you choose.

What they do for you is that they train in under a second, they need few examples when the features are good, and you can read every weight. A weight of zero point two six four per newton means something that a person can check, and the residuals show you where the fit is wrong.

The obvious alternative is a small neural network, which does not need you to make features by hand because it learns its own. With a picture as the input, that difference is decisive. But with a few measured numbers and tens or hundreds of examples, a network needs more examples to reach the same error, has many more settings to choose, and gives weights that nobody can read. The chapter overview shows ridge regression matching a small network on the depth camera problem at every dataset size.

However, these methods have costs. First, they can only draw the shapes that their features allow, so finding good features takes both knowledge of the problem and time. Second, logistic regression draws a straight dividing line between the classes in the space of its features, so a curved boundary needs curved features or a different method. Third, they cannot read pictures, point clouds or sound directly, because someone, or some network, must first turn the input into a short list of meaningful numbers. Finally, plain linear regression gives no error bar with each prediction, though the page on Gaussian processes covers a method that does.

The next part discusses the written alternative. The previous section compared these methods with a neural network, but the closer competitor is a formula that somebody wrote by hand. Book 5's least-squares fitting is the same maths used for a different purpose, which is fitting a shape whose formula is known, such as a plane or a circle, to measured points. Book 5's system identification finds the numbers in a physics formula, such as a motor's gain or a joint's friction, from logged motion, which is linear regression with features chosen by the physics. The written way wins when you know the formula, because then the features are exact and only a few numbers are unknown. Instead, linear regression as a learning method takes over when you only suspect the shape, and try several features to see which ones help. For yes-or-no questions, the written alternative is a hand-set threshold, such as "the grasp is safe if the force is above twenty-five newtons". So logistic regression is what you use when two or more numbers matter together and you want the threshold learned from logged results.

The final section is about using it in Python. Earlier, the page worked the weights of a line out from the readings, and listed the libraries that do it for you. This section joins the two, by showing the code that produces everything this page described. After reading it you will be able to calibrate a sensor and predict a chance from a table of readings, without writing any of the arithmetic yourself.

The code imports linear regression, ridge, and logistic regression from scikit-learn. To fit a line, it calls the fit function on the linear regression model, passing in the sensor counts and the true newtons, and then prints the weights and the offset. To use ridge regression, it creates a ridge model with an alpha penalty of one point zero and fits it to the same data. A larger alpha pulls the weights harder to zero. For weighted least squares, it calls the linear regression fit function again, but this time passes an array of trust values to the sample weight argument. To predict a slip, it creates a logistic regression model with a C value of one point zero, and fits it to the input features and the slip labels. It then prints the chance of a slip for new data by asking for the second column of the predicted probabilities. That column index is there because the function returns one column per class, and the second column is the chance of the class labelled one, which here is a slip.

As warned earlier, logistic regression applies a ridge penalty by default and its strength is set by C, where a smaller C means a stronger penalty. That is the opposite direction from Ridge, where a larger alpha means a stronger penalty.

The library gives you the solving. Linear regression finds the exact least-squares answer, and logistic regression runs the iterative fit, so you never write the normal equations or a gradient. It also gives you a tool that tries a list of penalties and keeps the best by cross-validation.

What you have to collect is the pairs. For the force sensor that means physically hanging known weights on the gripper and recording the counts, and no library can do that part. For the slip model it means recording grasps and writing down which ones slipped.

What you have to decide is the columns. If the sensor response bends, you add the bent columns yourself with polynomial features from scikit-learn, because linear regression fits a straight relationship in whatever columns you hand it. You also decide the penalty, and whether to scale the columns first, which matters for any penalty because the penalty treats all weights alike and a column measured in millimetres gets a very different weight from the same column measured in metres.
