Classical machine learning.

Not every learned model on a robot is a neural network, because the older learning methods, often called classical machine learning, are still used every day next to neural networks. This chapter covers those older methods, and this first page is its overview, so it answers four questions. What is classical machine learning? Why does it still matter on robot arms in 2026? Which methods does this chapter cover, and which one fits which job? And when does a small dataset make one of them a better choice than a network?

It is for a reader who has read the first chapter of this book, especially the pages on what a model is and how a model learns. You need to know what an example, a label, a weight, a test set, and overfitting are before you start, because this chapter builds on all five of them. Nothing else about machine learning is assumed in this chapter.

The first part of the page explains what classical machine learning is. The name is the place to start, because it says what these methods are not as much as what they are. Classical machine learning means the learning methods that were worked out before neural networks took over, and that are not themselves neural networks. Most of them date from the 1950s to the 2000s. They are still learning methods, because each one turns examples into a model that makes predictions, and none of them is a rule that a person wrote by hand.

For example, if a shop wants to guess how long a delivery will take from the distance it has to travel, and it has fifty past deliveries to learn from, nobody would build a large neural network for fifty rows. Instead, you would draw a line or a smooth curve through the fifty points and read the answer off it. In other words, classical machine learning fits a simple shape to a small table of numbers.

A neural network works differently, because it has many adjustable weights and can learn very complicated shapes, such as how pixels make up a mug. However, it needs many examples to set all those weights, and a lot of computing to train them. Instead, classical methods have far fewer settings, so they usually take a short list of numbers that already mean something, such as a distance, a force, or a joint angle. These input numbers are called features, and because these methods work on features rather than on pixels, they do not read raw pictures well.

The next section covers why classical machine learning still matters on robot arms in 2026. Fitting a simple shape to a small table of numbers sounds like a weak tool next to a neural network. The rest of this book is indeed about neural networks, because large networks now do most of the seeing and much of the moving on robot arms. However, classical methods still matter beside them, and they matter for four reasons.

First, small data. Many jobs on an arm come with tens or hundreds of examples rather than millions, because each calibration run, each logged grasp, and each demonstration costs robot time and a person's time. With so few examples, a classical method usually learns as well as a network or better. Second, error bars. Some classical methods, such as Gaussian processes, say how sure they are at every input with no extra work, so a robot can use that number to refuse an action, or to measure again, when the model is unsure. Third, speed. They train in seconds on an ordinary computer with no graphics card, and many of them predict in microseconds, which is fast enough for a control loop that runs a thousand times a second. Finally, explainability. You can read a regression's weights or follow a small tree's questions, so when the arm does something wrong a person can see why, and a safety review can check the reasoning.

Because each family covers the other's weakness, classical and neural methods are also often used together. For example, a pretrained network turns a picture into a short list of numbers, and a classical method then learns the robot's own job on top of those numbers.

The page then outlines the rest of the chapter. Because those four reasons do not all apply to every method, the chapter sorts its eight pages into two groups. 

The most used group holds four general tools, and each one of them learns from a table of numbers. Because they are so general, each can be used for almost any job where the input is a few measured numbers, and they are the ones a robot arm project reaches for first. These include linear and logistic regression, which use a weighted sum of features to predict either a number or the chance of a yes. Then there are decision trees and forests, which are chains of yes-or-no questions, grown either one tree at a time or many trees together. Next are Gaussian processes and Bayesian optimisation, providing a smooth curve with an error bar at every point, and a way to use those error bars to tune settings in a few tries. The fourth tool is nearest neighbours and locally weighted regression. These methods keep every example they were given, so they predict from the stored ones that are most like the new input.

The also used group holds methods with a narrower job. Two of them are built for motions and sequences over time, which is why they are common in robot learning from demonstrations. Another one is a helper that makes the data smaller before a second method uses it. The last one was once the leading method for classification, and it is used less now because trees and networks usually do better. This group includes mixture models and hidden Markov models, which describe data as overlapping blobs or tasks split into hidden phases. It includes movement primitives, which learn a motion from demonstrations that can be stretched to a new start and goal. It also covers Principal Component Analysis, or PCA, for shrinking data by turning many numbers into a few that keep most of the information. Finally, it includes support vector machines, which find a dividing line between two classes, placed as far as possible from both. 

You should read the four most-used pages first, and read them in order, because they are the ones a project reaches for first. The also-used pages can then be read in any order, whenever your own task needs them.

The next section puts these methods side by side so that you can pick one for a job you already have. The page includes a table listing each method, what it predicts, the data it needs, and an example of where it is used on a robot arm. The overall pattern in the table is that every method takes a short list of meaningful numbers as input, or a short recording of such numbers, and requires anywhere from a single demonstration up to a few thousand rows of data. For example, linear and ridge regression predict a number from tens of rows of hand-chosen features, such as turning a force sensor's raw counts into newtons. Decision trees and random forests predict a number or a class from hundreds to thousands of rows, which is useful for figuring out which logged grasps tend to fail. On the other hand, movement primitives predict a whole motion adapted to a new goal, using just one to ten demonstrations, like moving a pouring motion to a new cup position. None of the methods in this table reads a raw picture well, so raw pictures are left to the neural network chapters.

The next part of the page explains when a small dataset makes classical methods the better choice, using a test with real numbers. A robot arm has a depth camera, which measures how far away each pixel is. Its readings are a little wrong, and the error changes with distance, so to correct it the robot measures a flat board at known distances from 0.3 to 1.5 metres. Each measurement is one example, where the input is the distance and the label is the error of the reading in millimetres, with about 1 millimetre of random noise. 

The page shows a diagram and a table comparing four classical methods and a small neural network trained on this problem, with more and more examples each time. The network had one hidden layer of 64 neurons. Every method was trained 8 times on fresh random examples, and scored by the root mean square error against the true curve. This gives a typical size of the error in millimetres, so a lower number is better.

The diagram shows the error curves falling as the number of training examples grows from 10 to 640. Four things stand out in these numbers, and together they say when the extra power of a network is worth its cost. First, with 10 examples, the network is worse than the Gaussian process, ridge regression, and the boosted trees. Second, with 20 examples, the Gaussian process is clearly the best, with an average error of 0.56 millimetres against the network's 0.82 millimetres. Third, by about 80 examples the network has caught up with the Gaussian process and ridge regression, and from there on the three stay close to each other, all dropping down to around 0.1 millimetres by the end. Finally, on this problem the network never pulls ahead, because the input is one number and the curve is smooth, so a network's extra power has nothing to do.

A network pulls ahead when the input is large and complicated, such as a picture or a long recording, and there are many examples to learn from. In that case, no simple shape can describe the answer, so only a network can learn one. This gives a rule of thumb. With a few numbers in and tens to hundreds of examples, try ridge regression, a Gaussian process, or boosted trees first. With a picture, a point cloud, or a sound in, and thousands of examples or more, use a neural network, usually one that someone else has already trained, as explained on the page about fine-tuning. With both, a common mix is a network that turns a picture into a short list of numbers, and a classical method on top of those numbers.

The next section explains how this chapter connects to the rest of the book. It is not a separate world, since its methods connect backwards to Book 5 and forwards to the neural network chapters. Many classical methods share their maths with a written technique in Book 5, so the difference between the two books is the purpose rather than the formula. Book 5 fits a formula it already knows, while this chapter learns a shape that nobody wrote down. For instance, linear regression is least-squares fitting used to predict. K-nearest neighbours is built on nearest-neighbour search. A Gaussian mixture model is a softer form of the k-means method in clustering. A hidden Markov model tracks a hidden state over time, as the Kalman filter does, but for a state that jumps between a few phases. Movement primitives are learned versions of the curves in trajectory generation. And Bayesian optimisation is a careful relative of sampling-based optimisation, built for when each try is expensive.

Looking forward to the neural network chapters, they meet the methods of this chapter in several places. Movement models learn from demonstrations, as movement primitives do, but from camera pictures and many more demonstrations. Grasp quality models score grasps with a network, where a logistic regression or boosted trees would score them from a few numbers. The page on learned arm models describes the Gaussian-process and locally weighted work on learning how an arm moves, which came before deep networks. Learned dynamics models often use a small classical model to correct a physics formula. And the page on uncertainty and confidence explains how a robot uses an error bar, like a Gaussian process's, to decide whether to act.

The final section is about using these methods in Python. It adds the part the earlier tables leave out, which is how much code any of them takes. The answer is four lines, and knowing that changes where you expect to spend your time. The page shows a short Python snippet using the scikit-learn library. It imports a random forest classifier and functions for splitting data and scoring accuracy. It splits the data into training and testing sets, fits the model to the training data, and prints the accuracy score of the model's predictions on the test data.

In this code, X is a table with one row per example and one column per measured number, and y is the answer for each row. Every method in this chapter follows the same three calls, which are fit to learn from the training rows, predict to answer for new rows, and a scoring function to say how well it did. So to try a support vector machine instead, you just change the random forest classifier to the support vector classifier, and nothing else moves. That one property is why this chapter is worth reading before the neural network chapters, because you can try five methods in an afternoon.

The library gives you the whole algorithm and a set of defaults that are usually reasonable. It also gives you the splitting, the scoring, and a pipeline tool, which chains a preparation step and a model together so that new data is prepared in exactly the same way as the training data. 

What you have to collect is X and y, and what you have to build is the columns of X. That building is the real work of classical machine learning, and this chapter calls those columns features. A feature is one number you compute from the raw readings because you believe it carries the signal, such as the ratio of sideways force to grip force rather than the two forces on their own. Neural networks find their own features from raw input, and classical methods do not, which is the trade-off described earlier. 

What you have to decide is which method to try, the handful of settings it takes, and how the split is made. For the split, remember that frames recorded a few milliseconds apart are nearly identical, so for data logged from a moving arm you split by run rather than by row, as explained on the page about where the data comes from.
