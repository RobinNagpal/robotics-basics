Mixture models and hidden Markov models. 

This page explains three related methods. A Gaussian mixture model describes data as a few overlapping bell shapes. Gaussian mixture regression uses such a model to reproduce a motion that a person showed the robot a few times. A hidden Markov model follows a situation you cannot measure directly, such as the tool touching the table, from readings you can measure, such as force. The page answers four questions, and the sections below take them in turn. How does each one work? How is it trained? Where does it turn up on a robot arm? And when is a written rule the better choice?

It is for a reader who has read the earlier pages on what a model is, how a model learns, and the overview of this chapter. Nothing else about machine learning is assumed. Every number on this page comes from a real run of a script. The data is simulated, so that the true answer is known, but the methods themselves are real. Before this page, it helps to understand k-means clustering, because a Gaussian mixture is a softer version of k-means, and the predict and update steps of the Kalman filter, because the forward algorithm explained later works the same way.

The first section gives the idea in one sentence. When your data comes from a few different sources mixed together, such as two kinds of box, or a few steps of a task, you can describe it as a few bell shapes, one for each source, and then ask which source each reading most likely came from. 

For example, a post office weighs every parcel, where letters weigh a few tens of grams, small parcels a few hundred, and large parcels a few kilograms. If you plot all the weights you see three humps. Nobody labelled each item, but the humps tell you that there are three kinds, how common each kind is, and roughly how heavy each kind is. So a new item that weighs 350 grams is almost certainly a small parcel.

A bell, in this page, is the familiar bell-shaped curve that most measurements follow when they vary at random around a typical value. Its proper name is the Gaussian, or normal distribution. It has a middle, called the mean, and a width, called the standard deviation, and about two readings in three fall within one standard deviation of the mean.

The next part of the page covers Gaussian mixture models, which are a few overlapping bells. A Gaussian mixture model is a small number of bells added together, and each bell has its own mean, its own width, and its own share, which is the fraction of the data it accounts for. Since every reading comes from some bell, the shares add up to one.

To show one reading with two possible sources, imagine a robot arm lifts boxes off a conveyor, and its wrist sensor reads the weight of each box. Some boxes are empty packaging and some hold a product, but nobody tells the robot which is which. The script made 120 weights, which are 70 empty boxes around 410 grams and 50 full boxes around 505 grams. It then fitted two bells, without being told which box was which. 

A diagram shows the two bells fitted to the 120 box weights, and the chance each weight came from each bell. The fitted bells have means of 410 grams and 512 grams, both with a standard deviation of about 28 grams. Their shares are 0.62 and 0.38, close to the true 70 and 50 out of 120. The lower panel of the diagram shows the most useful output, because for any weight the model gives the chance that it came from each bell. A box of 440 grams has a 0.04 chance of being full, while a box of 455 grams has 0.23 and one of 470 grams has 0.64. The two chances are equal at 464 grams. This is a soft answer, because near the middle the model says it is not sure, instead of forcing a yes or no.

These bells are fitted by a method called expectation-maximisation, which solves a problem where each half needs the other half first. If we knew which box came from which bell, fitting each bell would be easy, because we could take the average and spread of its boxes. If we knew the bells, saying which box came from which would be easy, because we could compare the heights of the bells at that weight. We know neither, so the method guesses one and improves both in turn. 

First, it starts with a guess for each bell, which is a mean, a width and a share. Second is the expectation step. For each reading, it works out the chance that it came from each bell, using the current bells. This gives each reading a set of fractions that add up to one. Third is the maximisation step. It refits each bell from all the readings, but counts each reading only by its fraction for that bell. Finally, it repeats the expectation and maximisation steps until the bells stop moving. For the box weights, it stopped after 11 rounds. This method is like k-means with soft edges. K-means gives each point wholly to its nearest centre, while this gives each point partly to every bell, and also learns each bell's width and tilt.

The box weights were one number each, but in two dimensions each bell becomes an oval hill instead. Its covariance is a small table of numbers that says how wide the oval is in each direction and how it is tilted. Another diagram shows a run in two dimensions, using 200 points where a person dropped parts onto a tray in three loose heaps. The method starts from three large round guesses near the middle. Each point is coloured by its fractions, where a pure colour means one bell claims it, and a mixed colour means it is shared. After 3 rounds the ovals have stretched towards the heaps, but two of them still share one heap. Then after 39 rounds they have settled. The fitted means and shares are all very close to the true values. The diagram also shows the log-likelihood, which is a score for how well the bells explain the points, where higher is better. It rose from 533.3 to 673.6, and it never went down. That is always true of this method, making it a useful check on your own code.

The third section explains Gaussian mixture regression, which extracts a motion from a few demonstrations. While the previous section used a mixture to say which source a reading came from, regression turns the same mixture into a way of predicting one number from another. On a robot arm it is used to learn a motion from a few demonstrations. A demonstration is one recording of a person doing the motion, often recorded by hand-guiding, where a person holds the arm and moves it while the positions are recorded.

The script recorded five demonstrations of lifting a cup, carrying it and setting it down, giving the cup's height at 60 moments. Time is written from 0 at the start to 1 at the end, so that fast and slow demonstrations line up. First, every recorded point from all five demonstrations is put into one table with time and height, making 300 points. Second, a mixture of five bells is fitted to this table, so that each bell ends up covering one part of the motion, like the lift or the lowering. Each oval is tilted along the direction the height changes at that part. Third, to move the arm, you ask the mixture what the height should be at a given time. Each bell gives its own straight-line guess along its tilt, and the answers are blended, weighted by how much each bell covers that time.

A diagram shows the five ovals fitted to the five demonstrations, and the smooth height curve the regression reads from them. The curve peaks at 26.5 centimetres about half-way through. The regression also gives a spread at every moment, shown as a pale band. That spread is 8.9 millimetres at the start, 13.5 millimetres in the middle and 12.3 millimetres at the end. A controller can use this, holding the path stiffly where the demonstrations agreed, and letting the arm give way more where they varied. This is more than an average. The largest gap between this curve and a plain average of the five demonstrations is 7.9 millimetres, because the demonstrations do not line up perfectly in time. The mixture smooths over that, resulting in one smooth curve with no corners.

The fourth section introduces hidden Markov models, which track states you cannot see. The previous sections treated every reading as independent of the last, but this adds time. A hidden Markov model tracks a situation that changes over time and that you cannot measure directly, working it out from readings that you can measure. For example, a wiping tool comes down onto a table, presses, slides sideways, stops and slides again. The robot needs to know if it is approaching, in contact, or sliding. No sensor reads this state directly. The wrist sensor reads only the pressing force and the arm reads only the sideways speed, and both are noisy. The word hidden means the state cannot be read. The word Markov means the model assumes the next state depends only on the current state, and not on the whole history.

The wiping example needs all three parts of a hidden Markov model. First, the starting chances, which say how likely each state is at the first reading. Here, the tool almost always starts by approaching. Second, the transition chances, which give the chance of each next state one reading later. The page shows a table of these chances learned from a recording. The large numbers are all on the diagonal, meaning the state usually stays the same from one reading to the next. For example, if the tool is in contact, it has a 0.980 chance of staying in contact, and only a 0.017 chance of sliding. This is what lets the model ignore a single odd reading. Third, the reading chances, which provide a bell over the readings for each state. Approaching has near zero force and speed, in contact has 5.0 newtons and no speed, and sliding has 4.5 newtons and about 16 millimetres per second.

Those three parts describe the model, and the forward algorithm is how you use it live. It answers one question: given all the readings so far, what is the chance of each state now? It keeps one chance for each state, and repeats two steps at every new reading. The predict step moves the chances one step on with the transition table. The update step multiplies each state's chance by how well the new reading fits that state's bell, then scales the chances so they add up to one. These are the same two steps as the Kalman filter, but tracking a choice between a few states instead of a continuous number.

While the forward algorithm looks only backwards, the Viterbi algorithm looks at the whole recording instead. It answers what single sequence of states best explains the whole recording, so it is used to split a recording into steps after the fact. It works through the readings once from start to end, keeping the best way of arriving at each state. At the end it picks the best final state and follows the notes backwards. Because it looks at the whole recording, it can use a later reading to decide that an earlier moment belonged to one state rather than another.

The script fitted the model from one labelled recording, and then ran it on a new recording of 310 readings with 5 true changes of state. A diagram shows the noisy force and speed trace, the forward chances, and compares the states found by different methods. A table summarizes the results. Judging each reading alone by its nearest bell flickers between states 71 times and gets about 14 percent of the readings wrong, because one noisy reading can look like any state. However, both the forward algorithm and Viterbi report the true 5 changes, getting only about 1 percent of the readings wrong. Viterbi was very slightly worse per reading because it chooses the best whole sequence rather than the best state at each moment. Both place every change within two readings of the true moment. The forward algorithm is up to one reading late, because at each moment it has not yet seen the readings that follow.

The fifth section gathers how these models are trained. A mixture needs only the readings, with no labels, but it does need you to choose the number of bells. A common way is to fit several numbers of bells and compare them with a score that punishes extra ones, such as the Bayesian information criterion. Gaussian mixture regression needs a few demonstrations of the same motion, lined up in time. A hidden Markov model can be trained in two ways. With a labelled recording, training is just counting how often states follow each other and fitting a bell to each state's readings. Without labels, the Baum-Welch algorithm learns all three parts from the readings alone, but it needs more data and a sensible starting guess.

The sixth section lists where these are used on a robot arm. First, learning a motion from a few hand-guided demonstrations, where the spread can be used as a stiffness guide. Second, splitting a long demonstration into steps with Viterbi, so each part can be learned on its own. Third, tracking contact live from force readings with the forward algorithm. Fourth, spotting that something went wrong, acting as a failure detector if the model gives a very low chance to the current readings. Fifth, sorting items by a measured number without anyone labelling them first. Finally, describing where things usually are, giving a map of the likely places to look first.

The seventh section covers what goes wrong. The expectation-maximisation method can settle on a poor answer depending on where it starts, so the fix is to run it several times from different starts and keep the best score. A bell can also shrink onto a single point, so the fix is to add a small number, like 0.000001, to every covariance at every step. The number of bells or states has to be chosen by you; too few blurs things together, and too many fits the noise. A real state's readings may not follow a perfect bell shape, so you might need to use a mixture of bells for each state or filter the readings. The Markov assumption is not quite true either, because it assumes the chance of leaving a state is the same however long it has lasted. Finally, mixture regression only reproduces the demonstrated motion, because it does not know about new goals or obstacles.

The eighth section lists Python libraries you would use rather than writing the algorithms yourself. For mixtures, the place to start is scikit-learn, which has Gaussian mixture classes and a function for the Bayesian information criterion. For hidden Markov models, hmmlearn is the standard small library, providing fit, predict for Viterbi, and predict probabilities for the forward algorithm. For Gaussian mixture regression, there is a small library called gmr made for robot motions. Finally, pomegranate provides mixtures and hidden Markov models built on PyTorch, which is faster on large data and can run on a graphics card.

The ninth section explains why to choose these methods and what they cost. They turn a handful of readings into a model that gives a chance for every answer, not just a single answer. They train in seconds, and you can look inside them to check what each bell and transition means. A mixture beats k-means when the groups overlap or have different widths, and when you want to know how sure the answer is. A hidden Markov model beats a simple threshold when readings are noisy, because it uses the fact that states last. For learning a motion, mixture regression needs far fewer demonstrations than a neural network and no camera, but it only learns one motion. The costs are that you must choose the number of bells, the training needs several starts, the model is only as good as its bell shapes, and none of them can read pictures.

The tenth section looks at the written alternatives that do not use machine learning. For sorting readings into groups, clustering methods like k-means do the same job and win when the groups are well apart. For tracking contact, the written way is a threshold with a finite state machine, which wins when the readings are clean and the states are few, because it is easy to read and test. For reproducing a motion, the written way is to pick a few waypoints by hand and let trajectory generation join them smoothly, which wins when you can easily describe where the path should go.

The final section explains how to use these methods in Python. It describes a short script that fits both models using the scikit-learn and hmmlearn libraries. First, the code fits a Gaussian mixture to a set of readings. It sets the model to use three bells, allows each bell to be tilted, and tells it to run the fit from ten different starts and keep the best one. It then prints the Bayesian information criterion score to help you check if three bells was the right choice, and calculates the share each bell claims for a new set of readings.

Next, the code fits a hidden Markov model to three recorded force traces stacked together. It sets up a three-state model and passes the stacked traces along with a list of their individual lengths. This lengths argument is the detail that catches people. If you leave it out, the library treats the whole array as one single long trace, so it learns a transition from the last state of one recording to the first state of the next. Those transitions never happen on the robot, and the model would then report state changes that are not there. After fitting, the code runs Viterbi to find the best path of states for a new trace, and runs the forward algorithm to get the probabilities.

The libraries give you both of the algorithms this page worked through, hidden inside simple method calls. They also handle common failures for you, like running from several starts and stopping bells from shrinking to a point. What you have to collect is the recordings, keeping them separate for the hidden Markov model, or resampling them onto a common time axis for mixture regression. What you have to decide is the number of bells or hidden states, and how much shape each bell is allowed, such as whether it can be tilted or must remain aligned to the axes.
