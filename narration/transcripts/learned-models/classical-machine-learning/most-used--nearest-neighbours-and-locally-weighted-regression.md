Nearest neighbours and locally weighted regression. This page explains the learning methods that answer a new question by looking up the most similar stored examples. k-nearest neighbours copies the answers of the few closest examples, while weighted neighbours lets the closer ones count more. Locally weighted regression fits a small straight line around each new question, using only the examples nearby. These methods are old and simple, and they are still used on robot arms, from choosing a grasp to learning the arm's own dynamics while it moves.

The page answers six questions, taking them in turn. It covers how these methods predict a class or a number, why weighting the neighbours helps, and how locally weighted regression works, including why it was the classic way to learn an arm's dynamics online. It also explains why the methods fail when each example has many numbers, how the distance to the nearest examples can warn that a new input is unfamiliar, and where a robot arm uses them.

It is for a reader who understands basic model learning, including what an example, a label, a test set, and overfitting are. Every number mentioned comes from a real run of a simulated dataset written in NumPy, so the true answers are known exactly. It also helps to know how a program finds the closest stored points quickly, which is called nearest-neighbour search.

The first section gives the idea in one sentence. To answer a new question, find the stored examples whose inputs are most like it, and combine their answers, giving the closest ones the most say. For example, if you want to guess what a house will sell for, you do not write a formula for house prices. Instead, you find the five houses that sold most recently on the same street, of about the same size, and take the middle of their prices. If one of them is right next door and nearly identical, you trust it more than the others, and that is k-nearest neighbours with weighting.

The next part explains k-nearest neighbours, step by step. k-nearest neighbours, or kNN, does no training at all, because it simply keeps every example. To answer a new input, called the query, it first measures the distance from the query to every stored example's input. Second, it takes the k examples with the smallest distances, which are the neighbours. Finally, it combines their labels by taking a vote for a class, or an average for a number. k is a number that you choose, such as 5. The first step is the slow part when there are many examples, so programs often build a k-d tree, which is a structure that finds the neighbours without measuring every distance.

For classification, kNN takes a vote among the nearest. For example, an arm has logged 150 grasps, and each grasp has two input numbers: the object's width in millimetres, and how far the grasp was to one side of the object's centre, called the offset, also in millimetres. The label says whether the grasp held or slipped. In this simulation, a grasp holds if the offset is small enough for the width, because wide objects leave less room. To make it realistic, eight percent of the labels were flipped, as if some grasps failed for reasons the two numbers do not show. Take one query, a 60 millimetre object grasped 12 millimetres off centre, whose five nearest logged grasps are between 3.1 and 3.8 millimetres away. Three of them held and two slipped, so the vote is 3 to 2 and kNN predicts that it holds. The truth, from the rule, is also that it holds.

The page shows a diagram of the answer kNN gives at every point, with green for holds and red for slips, compared to the true boundary. It scores each setting on 4,000 new grasps. With k equals 1, every flipped label makes its own island of the wrong colour, so it is right only 88 percent of the time. With k equals 15, the islands vanish, because one wrong label is outvoted, and it is right 95 percent of the time. A larger k smooths the answer, but too large a k smooths away real detail. For example, with k equals 45, the vote reaches so far that it is right only 86 percent of the time. So, k is chosen by trying several values on examples held back for testing.

The next idea is weighted neighbours, where closer ones count more. In a plain vote, the fifteenth neighbour counts as much as the first, even if it is ten times as far away. Weighted neighbours gives each neighbour a weight that falls with its distance. The most common weight is one divided by the distance, so a neighbour 2 millimetres away counts five times as much as one 10 millimetres away. The answer is then the weighted vote, or the weighted average.

A table compares plain and weighted votes on the same 150 grasps across different values of k. With k equals 1, the two are the same, both scoring 88.3 percent, because there is only one neighbour. With a small k, weighting changes little. But with a large k, it matters a lot. At k equals 45, the plain vote drops to 86 percent because it lets far examples outvote near ones. However, the weighted vote gives those far examples little say and stays at 95 percent. So, weighting makes the choice of k much less delicate.

When measuring distance, units matter. The usual distance is the straight-line distance, which means squaring the difference in each input, adding them up, and taking the square root. This treats one unit of every input as equally important, so it is only fair if the units are comparable. In the grasp example, both inputs are in millimetres, and kNN with k equals 5 is right 95.6 percent of the time. If you give the width in metres instead, while keeping the offset in millimetres, a 60 millimetre difference in width counts as 0.06, while a 1 millimetre difference in offset counts as 1. The distance almost ignores the width, and kNN is right only 82.8 percent of the time. The fix is to standardise each input before measuring distance, which means subtracting its average and dividing by its spread. With both inputs standardised, kNN is right 95.1 percent of the time. Always do this when the inputs have different units, such as a joint angle in radians and a force in newtons.

The next section covers regression, and locally weighted regression. While classification votes among the neighbours, for a number instead, kNN averages the neighbours' labels. In a robot example, a joint's friction torque, in newton metres, depends on its speed, in radians per second. The robot has 40 measurements at speeds from minus 1 to 1 radian per second, each with noise of 0.04 newton metres. Plain kNN with k equals 6 averages the six nearest measurements, which draws a staircase shape because the answer jumps whenever the set of six neighbours changes. Weighted kNN weights them by one over the distance. This is smoother, but it bends towards each single measurement, noise and all.

Locally weighted regression, or LWR, goes one step further. For each query, it fits a straight line, but only to the examples near that query. It does this with weighted least squares. First, it gives every example a weight that falls with its distance from the query. In this example, the weight has a bell shape with a width of 0.12 radians per second. So an example 0.12 radians per second away gets a weight of 0.61, one 0.24 away gets 0.14, and one 0.36 away gets 0.01. Second, it fits a straight line to all the examples, using those weights, so that far examples have almost no say. Third, it reads the line's value at the query, and that value is the prediction. Finally, for the next query, it starts again with new weights. So LWR is not one model, because it is a new small model for every query. The line also lets it follow a slope, which an average cannot do.

The page illustrates one query near the end of the data, at 0.97 radians per second. The true torque there is 0.688 newton metres. The six nearest measurements all lie to the left of the query, between 0.85 and 0.89 radians per second. Their average is 0.644 newton metres, which is too low, because the torque rises with speed and every neighbour sits at a lower speed. Weighted kNN gives 0.642, for the same reason. But LWR fits a line through the nearby measurements and follows it out to 0.97, so its answer is 0.661 newton metres, which is closer to the truth. Its line rises by 0.24 newton metres for each radian per second, which is flatter than the true 0.40 because a few noisy measurements pull it, so it closes part of the gap, not all of it. 

A table scores the three methods. LWR has an average error of 0.019 newton metres overall, which is half the error of plain kNN. Near the two ends of the data, LWR's error is 0.016 newton metres, again about half the error of plain kNN. The ends are where an average suffers most, since all of its neighbours lie on one side. The width plays the part that k plays in kNN. A narrow width follows every bump, including noise, while a wide width smooths away real bends. So it is chosen by testing several widths on held-back examples.

The section then explains LWPR, which is used for learning an arm's dynamics online. An arm's inverse dynamics is the torque each joint needs to make a given motion. For a seven-joint arm, the input is 21 numbers, which are the angle, speed, and acceleration of each joint, and the output is seven torques. A physics formula can compute this, but it misses friction, cables, and wear. Researchers wanted to learn this mapping from the arm's own motion, while it moved. Plain LWR is too slow for that, because it fits a new line for each query from all the stored examples. So locally weighted projection regression, or LWPR, was the classic answer. 

First, it keeps a set of local models, where each one has a centre, a region it covers, and a small linear fit that is valid only in that region. Second, when a new measurement arrives, every local model near it updates its fit a little. The measurement is then thrown away, so that memory does not grow with time. Third, if no local model covers the new measurement well, LWPR creates a new one centred there. Fourth, each model also adjusts the size of its region, making it smaller where the mapping bends fast, and larger where it is nearly flat. Finally, to predict, it takes the answers of the local models near the query and averages them, weighted by how well each one covers the query. 

The word projection refers to one more trick. Within each region, LWPR finds the few directions among the 21 inputs along which the output actually changes, and it fits its line only along those. Real arm motion covers only a thin slice of all possible 21-number inputs, so a few directions are usually enough. LWPR learned the dynamics of real research arms in real time. Today, a small neural network often does this job, but LWPR's idea of learning online, from local pieces that do not disturb each other, is still useful when an arm must adapt while it works.

The next section is about the curse of dimensionality. Nearest-neighbour methods work well with a few inputs, but with many of them they fail. As you add input numbers, where each counts as one dimension, the space grows so fast that the stored examples become spread thinly. Every example ends up far from every other. So the nearest neighbour is then not near at all, because it is only a little nearer than the rest.

A diagram shows this with 2,000 random examples and 200 random queries, for 1 to 30 dimensions. It divides the distance to the nearest example by the average distance to all examples. In 2 dimensions this is 0.02, meaning the nearest example is fifty times closer than a typical one. But in 10 dimensions it is 0.37, and in 30 dimensions it is 0.63. So the nearest example is then almost as far as any other, and copying its label means little. Another way to see this is that to gather the nearest 1 percent of the examples inside a box, the box must span 10 percent of each input's range in 2 dimensions. But in 10 dimensions, it must span 63 percent of each input's range. The neighbourhood then covers most of the space, and it is no longer local. On a robot, this means using neighbours on a few carefully chosen input numbers, such as an object's width and weight, rather than on raw pixels. Real data helps a little because it usually lies on a thin slice of the space. A common trick is to let a neural network turn a picture into a short list of numbers first, and then search for neighbours among those.

The fifth section explains checking for unfamiliar inputs by distance. While distance loses its meaning with many inputs, with a few inputs it is useful in its own right. Any learned model can give a confident wrong answer for an input unlike its training examples, which is called out of distribution. The distance to the nearest training examples gives a simple check: if a new input is far from all of them, the model has not seen anything like it, and its answer should not be trusted. 

For example, a model predicts a correction torque from two joint angles. It was trained on 300 poses from the arm's usual work, but the robot then meets poses from anywhere in the range. To set a limit, you measure the distance from each training pose to its nearest other training pose. Inside the data, the typical value is 0.030 radians, and 99 percent of them are below 0.133 radians. So the check uses 0.133 radians as its limit. A new pose farther than that from every training pose is flagged.

A test on 3,000 random poses plots the error of a kNN prediction against the distance to the nearest training pose. 13 percent of the test poses passed the check, and their average error was 0.031 newton metres, with only 4.2 percent having an error above 0.1. The other 87 percent were flagged. Their average error was 0.393 newton metres, and 79 percent of them had an error above 0.1. The check caught most of the bad answers and let through mostly good ones, so the robot can refuse to use the correction, move more slowly, or ask a person. This check works for any model. For a neural network, you measure the distance between the network's internal numbers for the new input and for the training inputs, instead of between the raw inputs.

The next section covers how it is trained, and how much data it needs. kNN is not trained at all, because training just means storing the examples and building a search structure if there are many. Adding a new example is instant, making it a natural fit for a robot that learns as it works. You still choose k, or the LWR width, the weighting, and how to scale each input, by testing on held-back examples. The amount of data needed depends on the number of inputs. With one or two inputs, tens of examples give useful answers. But every extra input needs many more examples to keep the neighbours near. Beyond about 10 raw inputs, kNN usually does poorly unless the data lies on a thin slice. The examples must also cover the inputs the robot will meet, because kNN cannot guess beyond its data.

Section seven lists where these methods are used on a robot arm. First, reusing what worked. A robot keeps a store of objects it has grasped, holding a few numbers describing each object's shape and the grasp that worked. For a new object, it finds the most similar stored object and tries its grasp first. This is kNN with k equals 1. Second, predicting whether a grasp will hold, where a few numbers lead to a vote among similar past grasps. Third, learning the arm's dynamics online using LWR and LWPR, where a learned correction torque is added to the physics formula. Fourth, choosing an action from demonstrations. A robot stores the camera view and the action at each moment of some demonstrations, then finds the stored moments most like the current view and averages their actions. Fifth, flagging unfamiliar inputs by placing the distance check in front of any other model. Finally, finding the stored scene most like the current one, such as matching the current pose of a part to a library of stored poses.

The next section covers what goes wrong. Seven things happen often enough to look for. First, inputs in different units. One input with large numbers swamps the rest, so standardise every input before measuring distance. Second, too many inputs, which is the curse of dimensionality. Choose a few meaningful inputs or use a network to reduce them first. Third, noise in single examples. With k equals 1, every wrong label is copied, so use a larger k and weight the neighbours. Fourth, answers at the edge of the data. An average of neighbours that all lie on one side is biased, so use LWR's local line to reduce that bias. Fifth, being far from all data. kNN always answers, so add the distance check in front of it. Sixth, slow answers with many examples. Measuring every distance is slow, so use a search structure like a k-d tree. Finally, memory. kNN stores every example, which fills memory fast. Store short summaries instead, or keep only a chosen subset.

The page then lists libraries that provide these methods. Scikit-learn provides k-neighbors classifier and regressor functions, with an option for distance weighting. It also has a nearest neighbors function for the search on its own, and a standard scaler to standardise inputs. FAISS, from Meta, does fast nearest-neighbour search over millions of examples. Statsmodels has a function for locally weighted regression for one input. And the LWPR library is written in C with interfaces for Python and other languages. However, kNN and LWR are also short enough to write yourself in a few lines of NumPy.

Section ten explains why to use this, and what it costs. kNN and LWR predict by combining the labels of the stored examples most similar to the query. They need no training, learn new examples instantly, and every answer can be explained by pointing to the examples it came from. The obvious alternative is one global model, like linear regression or a small neural network, which must have the right shape everywhere at once. A straight line cannot follow a curve's bend, and a network can, but it must be trained again to take in new examples and may forget old ones. kNN and LWR fit the shape piece by piece, so a new example changes only the answers near it. Choose them when the inputs are few, the shape is unknown, and the robot keeps learning while it works. Another alternative is a Gaussian process, which gives an error bar and a smoother curve, but kNN and LWR stay fast with many more examples. The costs are that you must store every example, search them at each query, scale the inputs, and choose k or the width. They fail with many raw inputs and cannot predict beyond their data.

The next part compares this to the written alternative. Nearest-neighbour search on its own is a lookup table, where you store the grasps you have tested by hand and look up the nearest one. That wins when a person can list the cases ahead of time and there are few of them. But kNN adds the learned part, a vote or weighted average, so noise in one example does not decide the answer. For arm dynamics, the written alternative is system identification, which fits the numbers in a physics formula. It wins whenever the formula has the right shape, because it needs far fewer examples. But LWR and LWPR win for effects the formula does not describe, like friction changing with pose. The usual choice is both: the formula first, and a local learner on what it gets wrong.

The final section shows how to use it in Python. There are only a few calls, because the method has almost nothing to train. You import the k-neighbors regressor, nearest neighbors, and standard scaler from scikit-learn. You make a pipeline with the scaler first, because the units of each column decide which examples count as near. Then you fit the model with the training data and predict on new data. The pipeline ensures the scaling learned from the training rows is applied to the new data too. Scaling the two sets separately is a common mistake that quietly ruins the distances. To check how far an input is from anything seen before, you fit a nearest neighbors index on the training data and measure the distance to the new input.

When setting up the regressor, you can pass an argument to weight the vote by distance, where a closer neighbour counts for more. Leaving it out gives every neighbour an equal say. The library picks a data structure for you. With few columns, it builds a k-d tree or a ball tree to find nearest examples without comparing against every row. With many columns, it falls back to comparing against every row, which is the curse of dimensionality showing up inside the library. 

What you have to keep is the data. The fit function stores the rows and learns nothing, so all the cost moves to predict, and the saved model is as large as your dataset. If you delete the training rows, you have deleted the model. You must decide the number of neighbours, the scaling, and the distance above which you refuse to answer. A small number of neighbours follows the noise, and a large number smooths over real detail. The refusal limit has no default, so you set it by measuring how far each training example sits from its nearest neighbour and taking the value that 99 percent of them fall below. Finally, for locally weighted regression with a single input column, statsmodels has a function for it, which scikit-learn does not provide.
